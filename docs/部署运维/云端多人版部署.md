# FundPilot AI 云端多人网站

本包是可供托管的程序源码，尚未发布到公网。网站所有者需要自己的托管平台账号和持续运行的云端服务。个人电脑在正式上线后可以关机，用户用手机或电脑访问同一 HTTPS 网址。

## Ubuntu VPS 部署

已提供 Caddy HTTPS、Docker 非 root 容器、随机初始化口令、持久卷权限及每日 SQLite 在线备份的安装文件。新购 Ubuntu 24.04 VPS 可按 [VPS 部署与维护](../deploy/vps/README.md) 操作。安装时需要自己的域名及服务器访问权限；源码包准备完成不代表服务器已上线。

## 账号与数据

- 每人自行注册用户名并设置密码。用户名为 3～32 位字母、数字或下划线，也可以直接用邮箱地址（不超过 64 个字符，不发送验证邮件），密码为 8～128 个字符。
- 账号密码登录、注册和管理员初始化需要输入 6 位图片验证码（不区分大小写，每张只能用一次，5 分钟内有效；同一 IP 每 10 分钟最多获取 60 张）。验证码由 `research_captcha.py` 用 Python 标准库生成，不依赖 Pillow。短信验证码登录不需要图片验证码。
- 第一个账号是管理员，需要平台设置的初始化口令；以后注册的账号均为普通用户，不能取得管理员权限。
- 市场报告共用。关注列表与最近 20 份研究记录按账号保存；共享归档最多保留最近 40 份，过期归档会从个人记录移除。
- 公共模型、计划、数据连接和手动刷新由管理员管理。普通用户可查看报告，管理自己的关注、记录和密码。
- 修改密码会退出所有设备；管理员停用用户也会撤销该用户的所有登录。
- 登录最多维持 7 天，连续 24 小时未使用需重新登录，最多保留 5 台设备。
- 当前部署模板使用 `gpt-6.1-sol`，支持中度与极高推理；须由所选服务商实际提供模型权限。

## Railway 部署步骤

平台文档：<https://docs.railway.com/guides/dockerfiles>、<https://docs.railway.com/volumes>、<https://docs.railway.com/config-as-code/reference>。平台是否需要付款、试用额度和持续运行费用，以您创建服务时的平台报价为准。

1. 注册自己的 Railway 账号。将本包上传到自己的私有 Git 仓库，在平台新建项目并连接该仓库。也可用 Railway CLI 将解压目录上传到自己选择的项目；不要上传原电脑的整个项目目录。
2. 使用包内 Dockerfile 构建，入口为 `python -B -u backend/cloud_server.py`。保留单实例，不启用休眠；后台需要持续执行公共采集和计划。
3. 为服务添加持久卷，挂载路径为 **`/app/data`**。账号数据库、会话、个人关注与报告存于此卷。容器以 UID/GID `10001:10001` 运行，卷目录及已有文件必须允许此账号读写；镜像中的 chown 无法代替宿主机挂载目录的权限配置。没有持久卷就不能保证重部署后数据保留。
4. 在服务变量中设置：

   | 变量 | 内容 |
   | --- | --- |
   | `FUNDPILOT_STATE_DIR` | `/app/data/cloud` |
   | `FUNDPILOT_SETUP_TOKEN` | 自行生成至少 32 个字符的随机初始化口令，勿放入仓库 |
   | `FUNDPILOT_REGISTRATION_OPEN` | `1` 允许用户注册；`0` 关闭新注册，已有用户仍可登录 |
   | `FUNDPILOT_TRUSTED_PROXIES` | 平台实际直连代理的 IP/CIDR；不可猜测或设为全网。留空时忽略 XFF |
   | `FUNDPILOT_AI_API_KEY` | 可选；网站所有者自己的服务密钥，仅放平台变量 |
   | `FUNDPILOT_AI_BASE_URL` | 可选；服务商正式 HTTPS API 地址，云端拒绝 HTTP |
   | `FUNDPILOT_AI_MODEL` | `gpt-6.1-sol`，须具有该模型权限 |
   | `FUNDPILOT_AI_REASONING_EFFORT` | `medium` 或 `xhigh` |
   | `FUNDPILOT_AI_ENABLED` | 可选；默认不启用，管理员核验权限后再开启 |
   | `FUNDPILOT_FRONTEND` | 可选；镜像默认 `react`（新版界面）。设为 `legacy` 回到旧版 `dist/` 页面，重启生效 |

   可在本机终端运行 `python -c "import secrets; print(secrets.token_urlsafe(32))"` 生成初始化口令。此口令仅用于首次创建管理员；它与管理员登录密码不同。

5. 平台 Networking 中生成公开 HTTPS 域名。程序读取 `RAILWAY_PUBLIC_DOMAIN` 自动确定入口；其他平台请手动设置 `FUNDPILOT_PUBLIC_URL=https://您的域名`，不能带路径。平台负责终止 HTTPS，内部端口使用平台的 `PORT`。
6. 部署成功后打开 `/login.html`，输入初始化口令，自己选择管理员用户名与密码。创建完成后可删除平台中的初始化口令。不要设置或分享通用默认密码。
7. 管理员在“设置 → AI 研究”中检查连接，选择研究模型、计划并启用 AI。没有服务密钥时，公共量化研究仍可工作；实际数据取得与评分以页面证据和来源状态为准。
8. 分享网站的 HTTPS 网址，朋友点击“注册”设置自己的密码。无需分享管理员密码或 API 密钥。

公共认证请求按真实 IP 限制为 150 次/10 分钟；注册另有 5 次/小时/IP 和 200 次/小时全局限额。后台只信任已配置直连代理所传唯一 XFF 头的最右一个 IP；需要平台保证该末项来自真实连接，而非照传客户端的值。多层 CDN/代理链应先核对平台行为，按 VPS 文档配置真实 IP。

## 上线验收与维护

先用两个测试账号验证：A 添加关注后，B 的关注应仍为空；普通用户不能修改公共设置；退出后回到登录页；修改密码后旧登录失效。用手机 Wi-Fi 与蜂窝网络分别打开同一公开域名，确认不依赖家用电脑。

`/api/health` 只检查服务存活，不表示所有外部行情接口均可用。海外云节点的接口可达性与限流需要在部署地实测；采集失败会显示具体缺口，不生成虚假行情或评分。

平台持久卷应启用备份。不要直接复制正在写入的 sqlite3 文件；导出时使用 SQLite 在线备份或平台一致性快照，恢复时连同公共报告和配置一起恢复。

普通用户忘记密码时，管理员可在网站后台重置；密码原文不可查看。管理员无法登录时，网站所有者可在具有持久卷访问权的服务终端运行 `python cloud_admin.py`，按交互提示重置；密码不会通过命令行参数传入。

此电脑没有 Docker 运行环境；Linux 镜像实际构建、宿主机卷权限及公网 HTTPS 验收需要在目标服务器完成。测试不会使用生产账号或发起付费 AI 请求。

## 本机预览

新云端入口与原 `server.py` 本机版相互独立。在隔离数据目录中设置 `FUNDPILOT_CLOUD_DEV=1`、`FUNDPILOT_STATE_DIR=您自己的测试目录`，运行 `python backend/cloud_server.py`，默认访问 `http://127.0.0.1:8877/login.html`。首次创建测试管理员不要求初始化口令。

本地预览模式绑定本机，仅供验证，仍需电脑开机。正式托管不要设置 `FUNDPILOT_CLOUD_DEV`。
