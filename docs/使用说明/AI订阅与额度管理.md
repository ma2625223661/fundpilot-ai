# AI 订阅与额度管理

用户在网站注册后，通过订阅页的 QQ 客服联系管理员，提供网站用户名。管理员在“设置 → 用户管理 → 用户订阅与额度”中选择用户，然后：

1. 填写新增研究点数和延长天数，点“开通 / 续订并增加额度”；
2. 在“AI 调用次数”中填写**每天可调用次数**和**每个自然月可调用总次数**，点“保存调用次数”。

两项都设置后，用户才能自己点击发起 AI 研究。

## 谁在调用模型、谁付费

- 用户点击“生成 AI 研究”后，后台用管理员保存在服务器上的 API Key 调用模型。用户不需要、也不能填写密钥。
- 页面、接口、错误信息和日志都不返回 API Key 的原文或任何片段；设置页只显示“已保存 密钥（内容不显示）”。
- 服务商的实际调用费用由管理员统一承担；全站每日请求和 Token 预算保护仍然生效。

## 研究点数

- 点数是网站内的板块 AI 解读访问额度，不是人民币余额、Token 或用户自己的服务商额度。
- 生成或解锁一份解读：中度推理扣 1 点，极高推理扣 1.5 点。只有取得有效解读才扣点；连接或研究失败不扣点。
- 同一账号、同一内容版本只扣一次，多设备和并发重试不会重复扣点。

## 每日和每月调用次数

- 次数按北京时间计算：每天 0 点恢复每日次数，每月 1 日 0 点恢复每月次数。
- **只有成功调用模型才计 1 次。** 失败、复用已有的有效解读、重复查看已解锁内容都不计次数。
- 以下情况不发起请求，也不扣次数，并直接说明原因：管理员尚未设置次数、今日或本月次数已用完、AI 服务未配置或密钥不可用、报告已过期、板块证据不足。
- 用完时提示会同时写明“今日剩余 N 次，本月剩余 M 次”。
- 管理员修改次数后立即生效，不追溯已经用掉的次数。例如今日已用 1 次，把每日次数从 1 改为 3，今日还剩 2 次。
- 每月总次数不能少于每日次数。管理员账号本身不受次数限制，也不扣个人点数。
- 次数与点数同时检查：有次数但点数不足、或有点数但次数用完，都不能发起。

## 有效期和续订

新增点数累加到账号余额。延长天数从尚未到期的截止时间起算；已经到期或首次开通则从操作时间起算。填写 0 表示该项不增加。首次开通或已经到期的账号必须同时延长有效期。

点数用完或有效期结束后不能解锁新内容，已解锁的解读仍可复盘。“暂停 AI 服务”会停止新解锁并暂时隐藏已解锁内容，恢复后按原余额与有效期继续；暂停不会自动延长有效期。“停用账号”同时撤销该账号的全部登录。

普通用户在“我的 AI 订阅”查看剩余点数、有效期、已解锁份数、今日剩余调用、本月剩余调用及最近 30 条记录。管理员的备注对用户可见。开通、续订、暂停、恢复、调整次数及解锁记录都保存在账号 SQLite 数据库。

## 部署和验证

本机登录入口和云端多账号入口共用同一权限逻辑。升级时只新增调用次数表和用量表，不改变已有账号、密码、关注列表、研究记录、点数或后台加密密钥。**升级后，已有用户要等管理员为其设置调用次数后才能自行发起 AI 研究。**

定时研究仍需要运行中的后台。订阅确认与开通暂由管理员手动完成。

验证命令：

```powershell
runtime\python.exe -B tests\run_backend.py -q test_research_subscriptions test_ai_call_limits test_manual_sector_ai test_cloud_accounts test_local_accounts
cd web; npm run test:components
```

测试全部使用隔离账号和模拟 AI 报告，不调用收费模型。
